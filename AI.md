# Function Plane — Agent Onboarding

Notes for the next agent working on this repo. Read this before editing.

---

## 1. What this is

**Function Plane** is a mobile-first puzzle game where players write mathematical equations (y = f(x), implicit F(x,y) = 0, sums, derivatives, integrals) to guide a bouncing ball through a set of stars on a coordinate plane. Fewer/simpler equations = higher star rating.

**Deployment targets:**
- **Android**: shipped as an APK via **Capacitor 6**, opened in Android Studio
- **iOS**: planned — `@capacitor/ios` is installed but the `ios/` folder hasn't been generated (needs a Mac; user does not have iOS running yet)
- **Web (PWA)**: deployed to **Cloudflare Pages** as a static site — same codebase, no changes needed

---

## 2. Architecture — the ONE thing you must understand

**There is no bundler.** The app uses:
- **React 18** and **ReactDOM** loaded as UMD `<script>` tags from `function-plane/vendor/`
- **JSX pre-compiled** to plain `.js` files by `scripts/build-jsx.js` (uses `@babel/core` + `@babel/preset-react`, `runtime: 'classic'` → still emits `React.createElement`)
- Compiled `.js` files sit **next to** their `.jsx` sources in `function-plane/src/` and are the ones actually loaded by `index.html`

### The critical workflow rule

**After editing ANY `.jsx` file, run `npm run build:jsx`** from the repo root, or the change won't reach the browser (`index.html` loads `.js`, not `.jsx`).

```powershell
cd C:\Users\Redmi\Documents\GitHub\Function-Space
npm run build:jsx
```

You can safely re-run — it's idempotent and takes ~2 seconds.

### Why no bundler / no runtime Babel?

Both were tried. The Capacitor Android WebView **silently fails** to load `<script type="text/babel" src="...jsx">` because Babel-standalone uses XHR to fetch each JSX file and eval it — some Android WebView versions block this. CDN loads with SRI checks also break. Pre-compiling everything to plain JS with local vendor scripts is the only combination that works reliably across browsers, Android WebView, and iOS WebView.

## 5. Code style

Read these before writing code — they reflect the project's actual conventions.

### General

- **No emojis** in code unless the UI legitimately displays one.
- **Terse comments only**, explaining *why*, not *what*. Well-named identifiers do the "what" job. See the existing code — comments are rare and always earn their spot.
- **No premature abstraction.** A three-line helper used once is fine as inline code.
- **No backwards-compat shims.** If a field is renamed, rename callers. Don't leave `// old field` re-exports.
- **Two-space indent, single quotes, no semicolons trailing on JSX props.** Match the surrounding file.

### React specifically

- No JSX bundler, so **no import statements** — everything is on `window` (`window.LevelScreen = LevelScreen` at the end of each file). Each file loads in the order defined in `index.html`.
- Aliased destructuring at top of files: `const { useState: useSL, useRef: useRL } = React;` — this avoids collisions in the global-hooks world. Follow the convention when adding a new file.
- Components render as global functions. Cross-file references work because everything is on `window`.

### Load order matters

`index.html` has a fixed script order. New files must be added there AND to `sw.js`'s `SHELL` list. Order matters: e.g. `data.js` must load before `main-screen.js` because MainScreen calls `getPack()`. `app.js` must be last (it calls `ReactDOM.createRoot(...).render(<App/>)`).

### `mount()` guard in app.jsx

`app.jsx` polls with `setTimeout(mount, 30)` until every global it needs is defined. When adding a new top-level component that `App` renders, **add its `typeof` check** to the guard, or you'll get a race where React tries to render `<AdminScreen>` before `admin-screen.js` has finished parsing.

## 6. Service worker — the most-forgotten step

**Every time you add a new source file OR change bundled assets, do BOTH:**

1. Bump the cache version at the top of `function-plane/sw.js`:
   ```js
   const CACHE = 'fp-v22';  // was fp-v21
   ```
2. Add the file to the `SHELL` array so it's precached.

Without the bump, users get the old cached SW + old assets forever. Symptoms: your code change works in DevTools with "Disable cache" checked, but breaks on real installs.

Current version: check `sw.js` line 1. When in doubt, bump it.

## 7. Physics engine (level-screen.jsx)

This is the trickiest subsystem — read the header comments in `physicsStep()` before editing.

Key facts:
- **Explicit curves** (`y = f(x)`): perpendicular-distance collision. The ball's contact with a sloped curve is measured against the tangent line, not the ball's vertical column. This is why the ball glides smoothly on any slope — do NOT revert to sample-based `ball_bottom vs cy(x)` detection (it caused the "jagged slope" bug).
- **Implicit curves** (`F(x, y) = 0`): marching-squares render + `F/|∇F|` distance-to-surface collision.
- `SUB_STEPS = 20` substeps per animation frame — required for the tunneling detection to catch fast/steep passes.
- `PHYSICS_CONFIG.energyRetention` (physics-config.js) is applied **only on real bounces** (`-vn > 1.5`), not on sliding contact. Otherwise a ball rolling down a slope loses all momentum in ~0.5 s.
- `SLOPE_MAX = 10` caps the slope used in collision math. Without it, near-vertical curves yield `√(1+m²) → ∞` and fling the ball miles.
- Level ends **0.5 s after the last star is collected** (`wonAtS` timestamp), not when the ball falls off. Recorded finish time is `wonAtS`, not the wind-down endpoint.

## 8. Scoring engine

Lives in `classifyEquation()` and `detectClass()` in `level-screen.jsx`.

**Critical regex gotcha:** function-name matching uses `(?<![a-z])` (negative lookbehind), NOT `\b`. Reason: `\b` doesn't fire between two word characters, so `\bcos\(` fails to match `4cos(` (both `4` and `c` are word chars). This bug bit us — see git history around the `(x-0.5)^2` / `4cos(x)` fixes. If you touch these regexes, test with:

- `4cos(x)` → trig (score ~45)
- `2log(x)` → log (score ~50)
- `acos(x)` → inverseTrig (must NOT match plain trig regex)
- `(x-0.5)^2` → quadratic (must match, `)^N` pattern is needed alongside `x^N`)

**Score = complexity + 20 × (number of user equations).** Pre-placed equations don't count.

## 9. Custom math keyboard

- Native mobile keyboard is suppressed via `inputMode="none"` on equation inputs.
- The custom `MathKeyboard` in `keyboard.jsx` has two pages: `basic` (sin/cos/log/digits) and `advanced` (arcsin, Σ, d/dx, ∫, n variable).
- **Domain-restriction inputs** use a separate `NumPad` (also in `level-screen.jsx`) that opens when the user taps a domain value button. This prevents the native keyboard from covering the custom one — required because `<input type="number">` cannot suppress the native keyboard reliably on Android.
- When any keyboard is open, `EquationsPanel` sets `maxHeight: 'none'` so both the equation rows and the keyboard fit — the graph area shrinks accordingly.

## 10. Splash screen (index.html)

Non-obvious timing:
- Held at `opacity: 0` for `revealDelay = 500 ms` — a fast boot never flashes the splash.
- Once revealed, stays visible for at least `minVisible = 350 ms` so it doesn't blink out.
- Hidden only when **both** `document.fonts.load(...)` and the first React render complete.
- Hard fallback: `setTimeout(hide, 7000)` prevents a stuck splash on slow networks.

If you change fonts, update the `document.fonts.load(...)` calls in `fontsReady()`.

## 11. Supabase — external state you can't see from the code

Credentials: `function-plane/src/supabase-config.js` (project URL + anon key are checked in).

### Tables (schemas managed in Supabase dashboard, not in this repo)

| Table | Purpose | Notable columns |
|---|---|---|
| `profiles` | User profile (name, avatar, total stars) | `id` (PK, FK to auth.users), `name` (unique, case-insensitive), `avatar`, `total_stars`, `is_premium` |
| `progress` | Per-user progress blob | `user_id` (PK), `data` (JSONB — the whole progress object), `updated_at` |
| `level_scores` | Per-level completions for leaderboards | `(user_id, pack_id, level_index)` composite PK, `best_score`, `stars`, `best_time` |
| `pack_overrides` | Admin edits to pack metadata | `pack_id` (PK), `name`, `allowed_class`, `is_hidden` |
| `level_overrides` | Admin edits to level data | `(pack_id, level_index)` composite PK, `ball_x`, `ball_y`, `stars` (JSON), `score_goal`, `eq_goal`, `preplaced` (JSON), `name` |
| `achievement_overrides` | Admin-authored custom achievements | `id` (PK), `kind` (one of `ACH_KINDS` in achievements.jsx), `name`, `description`, `threshold`, `pack_id`, `level_index`, `is_hidden` |
| `push_subscriptions` | Web Push endpoints | `endpoint` (PK), `user_id`, `keys` |

**RLS**: Users can read/write only their own rows. Overrides tables have a policy that restricts writes to profiles named exactly `Test Account` (case-sensitive, no trailing spaces) — this is how admin permissions are gated. See `isAdmin()` in `accounts.js` line 510.

### The `level_scores.best_time` migration

Older Supabase projects may not have the `best_time` column. `_uploadProgress` in `accounts.js` catches the missing-column error and retries the upsert without it. If you're onboarding a new environment, run the migration or the time leaderboard silently doesn't work.

### Admin account convention

There is exactly one admin identity: **the profile whose `name` is `Test Account`**. Everything gated by admin (writing overrides, granting premium via `setPremium()`, seeing hidden packs) checks this string. Don't hard-code additional admins in code — do it via the DB / RLS if it ever needs to expand.

## 12. Progress data shape (localStorage + Supabase `progress.data`)

```js
{
  "r-I":  { stars: [3,3,2,-1,...], best: [180,220,310,...], bestTime: [1.2,...], maxScore: [220,...] },
  "r-II": { stars: [null, null, ...], best: [...], bestTime: [...], maxScore: [...] },
  "s-lin": { ... },
  ...
}
```

Semantics:
- `stars[i]`: `null` = locked, `-1` = unlocked but unplayed, `1..3` = rating earned
- `best[i]`: **lowest** score used to win (lower = better rating)
- `bestTime[i]`: **fastest** win time in seconds
- `maxScore[i]`: **highest** score used in a winning run — added for the "Big Brain" achievement (beat any level with equation > 100 pts). Older exports may lack this field; handle `?? null`.

Merging is done in `accounts.js::_mergeProgress` — max of stars/maxScore, min of best/bestTime.

## 13. Achievements

Two sources are merged at render time by `getAchievementList()` in `achievements.jsx`:

1. **Built-in** — `BUILTIN_ACH_LIST` (17 total). Each has an inline `check(progress) → boolean`.
2. **Custom (admin-authored)** — rows from `achievement_overrides`, built via `buildCustomAchievements(rows)`. Each row picks a `kind` from `ACH_KINDS` (a fixed set of predicate templates: `total_stars`, `total_levels`, `pack_complete`, `pack_full_gold`, `any_3stars`, `min_score`) and supplies parameters.

**Adding a new built-in**: append to `BUILTIN_ACH_LIST`, `npm run build:jsx`, bump `sw.js` cache. That's it. Unlock toasts are handled by `app.jsx`'s effect on `[progress, overridesRev]`.

**Adding a new custom `ACH_KINDS` template**: extend `ACH_KINDS` in `achievements.jsx` AND wire its params in `admin-screen.jsx`'s `AchievementEditor`.

## 14. Level & pack data

- Base data lives in `data.jsx` (`LEVELS`, `ROMAN_PACKS`, `SPECIAL_PACKS`).
- **Overrides from Supabase** (`FP_LEVEL_OVERRIDES`, `FP_PACK_OVERRIDES`) merge in at runtime via `applyOverrides()`. Admin panel writes those.
- Unlock thresholds: Roman pack N unlocks at **27/30 stars in pack N-1** (see `pack-selector.jsx` — `need = 27`). Themed packs use `SPECIAL_UNLOCK_STARS` in `data.jsx`.
- Themed packs enforce equation class via `allowedClass` (linear / quadratic / trig / exp). Enforcement runs in `level-screen.jsx::classWarning`.

## 15. Capacitor / WebView gotchas

- **`Cap.Plugins.App.addListener(...)` return shape varies**: Capacitor 6 returns the handle synchronously; older versions returned a Promise. `app.jsx` handles both (checks `typeof ret.then === 'function'`). If you add more listeners, use the same pattern.
- **Hardware back button** is hooked in `app.jsx` — pushes navigations onto `navStackRef` and pops on Android back press, falling back to `exitApp()` at the root. Don't add navigation via anything other than `navigate()` / `navigateBack()` or the back button gets confused.
- **No `type="text/babel"`, no CDN scripts, no runtime eval.** The WebView will fail silently. Everything must be plain compiled JS loaded from local paths.

## 16. Common pitfalls (learned the hard way)

- Edited a `.jsx` file, refreshed, no change → forgot `npm run build:jsx`.
- Deployed new build, users see the old app → forgot to bump `sw.js` cache version.
- New source file loads locally but not on Android → forgot to add it to `index.html` script tags AND `sw.js` SHELL list.
- Regex to match function names uses `\b` → coefficients like `4cos(x)` won't match. Use `(?<![a-z])`.
- Wrote a Promise-returning `useEffect` handler → React ignores the returned Promise (only cleanup function is respected). Use `.then()` inside, don't `async` the callback itself.
- Added a component to `app.jsx`'s routing → forgot to add its `typeof` check to `mount()` → race condition on cold load.
- Physics feels off → check if you accidentally re-broke the "only apply `energyRetention` when `-vn > 1.5`" gate. That gate is what makes ball-on-slope not die instantly.
- iOS folder mysteriously missing → it's never been generated. Needs a Mac + `npm run cap:add:ios`.
